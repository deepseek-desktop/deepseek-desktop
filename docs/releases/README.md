# 发布说明维护

README 介绍产品与使用入口，CHANGELOG 记录变化历史，GitHub Release 帮助用户决定是否升级及下载哪个安装包。发布说明使用简体中文，只描述对应版本实际交付的内容。

## 排版约定

1. **版本摘要**：用一两句话说明本版重点；写明 Harness 基线时，核对该 Tag 的 `harness/toolchain-lock.json`，不要沿用上次说明。
2. **下载与安装**：在正文前部以表格列出五个安装包和 `SHA256SUMS`，直接链接当前 Tag 的实际资产，方便用户无需展开 Assets 即可下载。
3. **更新内容**：按需使用“新增”“修复”“改进”分类，优先描述用户可感知的变化；没有内容的分类直接省略。
4. **升级说明**：明确安装方式、数据保留方式及必要操作，区分 Desktop 与 Harness 更新。不要默认每次升级都需要改配置。
5. **验证与限制**：区分源码测试、原生构建、下载校验与实机验收。写明实际平台及模型范围，不能将构建成功写成所有平台已实测。
6. **源码与完整变更**：链接本版 Tag；存在相邻有效版本时，可补充 compare 链接。

Release 标题直接使用 Tag，例如 `v0.1.6.2`；正文无需再重复一级产品标题。使用标准 Markdown 标题、列表、表格和代码块，便于 GitHub 与桌面更新摘要共同显示；不要依赖 HTML 折叠块、脚本或远程图片展示重要信息。

## 生成与维护

- 通用内容维护在 [发布模板](../../.github/release-notes-community.md)，本次变化维护在 [CHANGELOG 的“未发布”段](../../CHANGELOG.md#未发布)。模板不硬编码某次 Harness commit、工具链版本或实测结论。
- 正式工作流继续通过 `scripts/prepare-ci-release-notes.mjs` 生成正文，自动检查完整资产集合、唯一下载/变化标记及非空变化，再填入当前版本的下载表格与源码链接。
- 发布完成后，将 CHANGELOG 中已交付的条目归档到版本段，并同步 README 与使用指南中的未发布提示。补齐已完成的下载校验、实机验收和永久证据链接，将最终 Release 正文保存为本目录的 `<四段版本>.md`。
- 本目录的版本文件只描述 DeepSeek Desktop 社区版的发行事实，并与对应 Release 正文逐字一致，因此不加入仅供仓库阅读的标记或来源声明。下游 fork 同步上游时自行替换或移除这些文件，上游不为此改变存放结构。
- 本目录版本文件是对应公开正文的归档。编辑历史说明时使用该版本文件，不从当前“未发布”段重新生成历史内容；同步 GitHub 后核对正文一致，保持 Tag、安装包、签名状态与预发布标记不变。
- 日常安装说明可链接默认分支；历史配置与验收证据应链接固定 Tag 或 commit。只查询资产 metadata 不代表已下载校验。

发布正文更新示例（在仓库根目录执行，版本号替换为实际目标）：

```bash
gh release edit v0.1.6.2 \
  --repo deepseek-desktop/deepseek-desktop \
  --notes-file docs/releases/0.1.6.2.md
```

这条命令只更新说明。正式创建发行的流程、平台门禁和 Tag 规则见 [多平台发布指南](../zh-CN/distributed-release.md)。
