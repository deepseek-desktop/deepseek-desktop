# ADR-013：保持窗口菜单位置，仅修正 macOS 子菜单锚点

## 状态

已采用，补充 ADR-011，不改变三平台统一的窗口内菜单布局。

## 决策

“文件 / 编辑 / 视图 / 窗口 / 帮助”始终位于应用窗口顶部。macOS 系统栏只保留既有最小应用菜单和隐藏的编辑快捷键，不在屏幕顶部新增另一套功能菜单。

macOS 原先以鼠标位置弹出原生子菜单，忽略窗口内标题锚点，导致菜单覆盖标题且随点击位置漂移。改为将标题左下角从内容坐标转换为 AppKit 屏幕坐标，使用原生 NSMenu 展开与屏幕边界处理，不改窗口、WebView 或布局。

必须向 `popUpMenuPositioningItem:atLocation:inView:` 传入空视图，保留屏幕坐标模式；不能直接改用 Tauri `popup_at`，它在锁定版本中会绑定 Tao 根 NSView，重新引入已知 macOS 26 视图生命周期崩溃路径。保留主线程校验、菜单重入门闩和输入事件防护，不移动光标、不主动改变焦点。

通过锁定 Tauri 的 ContextMenu 原生对象访问 NSMenu，所有权持续到菜单关闭，不新增依赖。该访问依赖 Tauri 的内部父 trait，升级 Tauri/muda 时必须重新核对接口、线程和生命周期契约，并复测实际 macOS 菜单定位与连续开关。Windows/Linux 继续使用已有 `popup_at` 路径。
