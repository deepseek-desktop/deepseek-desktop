# ADR-010：跨平台窗口内统一菜单

## 状态

已被 ADR-011 取代。

## 决策

macOS、Windows 与 Linux 的用户功能菜单统一显示在 DeepSeek Desktop 原生窗口内容区顶部，固定为“文件 / 编辑 / 视图 / 窗口 / 帮助”五组。菜单标题由本地管理 Shell WebView 三语渲染，展开项由 Tauri 创建原生系统菜单，继续复用系统编辑、窗口与关于能力。

工作台仍是没有通用 Tauri IPC 权限的独立 Runtime WebView。桌面管理页直接显示壳层菜单；显示工作台时，Desktop 使用初始化脚本注入固定菜单条和三语标题，并为页面内容保留 34px 顶部空间。按钮只导航到当前受管 loopback Origin 下的保留路径，Rust 在导航发生前校验 Origin、菜单名和坐标，弹出原生菜单并拒绝实际跳页；不向 Runtime 页面开放 Tauri IPC 或桌面命令。

macOS 只保留操作系统要求的应用菜单，用于关于、服务、隐藏和退出；完整功能菜单不再同时出现在系统菜单栏。Windows 与 Linux 移除原生窗口框架中的重复菜单。

## 理由

- 三个平台拥有相同位置、相同结构和相同三语文案，用户无需适应平台差异。
- 原生弹出项保留复制、粘贴、窗口控制等系统语义和可访问性。
- 工作台安全边界不变，只有 `main` WebView 拥有壳层能力；Runtime 页面只能请求打开受约束的原生菜单，不能直接执行菜单动作。
- 注入菜单使用 CSS 逻辑像素，和 Runtime 页面在各系统缩放设置下共同缩放，不依赖平台子 WebView 坐标实现。

## 后果

- Vue 菜单标题、Rust 菜单项标签和三语资源必须同步维护。
- 调整菜单高度时必须同步修改 Shell CSS 与 Runtime 菜单初始化脚本，并更新布局回归。
- Windows 与 Linux 真机发行仍需由对应平台验证原生弹出菜单外观和窗口命令。
