# ADR-015：仓库更新复用生产部署闭包

## 决策

仓库源码不能直接充当安装目录。`harness-sync` 与仓库更新共同调用 `scripts/lib/harness-deployment.mjs`，使用上游部署聚合包执行生产 deploy，再补齐 workspace peer 并物化链接。CLI 入口和版本取自唯一 `bin.dsh` 声明。

更新候选只从当前交付闭包带入显式桌面扩展根包及其缺失依赖；候选已有核心服务优先，必需 peer 缺失时拒绝准备，不混装旧 Harness 核心。准备脚本嵌入 Desktop，子进程使用内置 Node/pnpm 和既有超时、进程树清理及脱敏边界。源码暂存和候选都只写应用数据目录。

后台维护与工作台首次启动共享一次性候选激活门闩。哪个路径先到达都必须完成 pending smoke 和原子切换后才能启动服务，避免旧内核已经运行但 current 指针显示新版；之后的联网检查不阻塞工作台启动，激活工作不占用窗口线程。

桌面搜索扩展和固定市场组件识别公共设置服务接口形态，支持服务自身的 `installSection`。未安装桌面模型路由补丁的 Harness 可通过公共设置描述中的显式 endpoint、模型协议与凭据引用解析路由；已注册适配器解析器优先，不按厂商身份猜测。没有完整元数据或出现多重声明时拒绝搜索，不影响聊天。

Harness 的认证 Cookie 按主机存储，随机端口重启会留下旧项。Supervisor 只在重新导航工作台时删除受管 loopback 主机上符合 Harness 认证命名的 Cookie，然后由新会话重新握手；同次启动内的设置开关保留页面与全部会话状态。窗口菜单位置不变。

## 验证边界

共享部署 helper 的匿名夹具覆盖传递依赖、核心隔离、缺失依赖与输入文件恢复；搜索夹具覆盖动态路由和歧义拒绝。候选 smoke 检查真实服务、HTML、插件脚本与进程清理，原生应用再验证准备、重启切换及内置恢复。其他平台的本机源码更新验收不能以 macOS 结果替代。
